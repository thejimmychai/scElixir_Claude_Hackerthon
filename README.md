# Universal Developmental Reprogramming Pipeline — application

A frontend + backend application built from the static blueprint per
[`docs/CLAUDE_CODE_HANDOFF.md`](docs/CLAUDE_CODE_HANDOFF.md). It serves the 6-stage
pipeline (Atlas → GRN → in-silico reversal → TF combo + small-molecule rejuvenation →
deep-learning fate validation) over the Section-4 API. The lung `AT2 → fetal
distal-tip` case is fully worked. Other organs can be added as bundles
([docs/ORGAN_BUNDLE.md](docs/ORGAN_BUNDLE.md)).

**Status by phase:** [docs/IMPLEMENTATION_STATUS.md](docs/IMPLEMENTATION_STATUS.md) maps
each item of the handoff plan to what is in the code, and lists what still needs
external compute.

## Run it

Three ways to launch, in order of capability:

**1. Double-click (no terminal, no server).** Open `frontend/standalone.html` in any
browser. It is one self-contained file. The UI works offline for the lung reference case,
using an embedded snapshot of the backend's own responses, and switches to live data
when the server below is running.

**2. Full app (server + UI).** Only a Python 3.8+ interpreter is required (no
`pip install`, no Node). From this directory:

```bash
python3 -m backend.app          # or ./run.sh
```

The server prints the address it bound. It uses port 8765 when it is free. If another
program holds that port, it uses the next free one, for example 8767, and says so. Pin a
port with `--port 8770`. Stop with Ctrl-C.

Check what this machine can actually run:

```bash
curl http://127.0.0.1:8765/compute/status    # use the port the server printed
```

> If `./run.sh` reports "permission denied", run `chmod +x run.sh` once, or use
> `python3 -m backend.app`. The server must keep running in its terminal.

**3. Original blueprint.** `frontend/reprogramming_pipeline.html` is the pre-refactor
fully-inline standalone, kept for reference.

Run the regression suite (42 tests; nothing needs the network or optional packages):

```bash
python3 -m unittest discover -s tests -v
```

## Why standard-library, not FastAPI

The handoff *suggests* FastAPI. This build uses `http.server` so the app boots anywhere a
Python interpreter exists, with no install step. The heavy compute (scVI, CellOracle,
PertFormer) lives on separate GPU hosts and this bundle is the portable reference. **The
request and response shapes are the contract and match Section 4**; a later port to
FastAPI is mechanical.

## Architecture

```
backend/
  app.py            # routing, validation (400 on bad input), artifact-first serving
  config.py         # paths (data/reference, data/external, data/results, data/organs), reference case, GRN table
  data_loader.py    # seed + data/reference CSV/JSON (csv module, no pandas)
  registry.py       # organs/layers/states (incl. bundles) + the "what's computed" index
  artifacts.py      # durable results keyed by full parameter identity (guardrail 5)
  capabilities.py   # engine/module/file/weights/input report + per-stage `requires` lists
  organ_bundles.py  # organ.json validator and loader (Phase 5)
  jobs.py           # in-process async job queue; failed jobs carry `requires`
  stages/           # one runner per stage (A–F): real result, or honest not_computed / refusal
  engine/           # reused engine scripts (wrapped, not rewritten)
frontend/
  index.html        # shell (markup + styles)
  src/api.js        # fetch wrappers; snapshot then seed fallbacks when the backend is down
  src/app.js        # boot, selectors, ribbon, stage panels, run-and-poll action
  src/stages.js     # per-stage render functions (consume the API payloads)
  src/state.js      # selection store
  src/seed.js       # embedded seed payload (generated)
  standalone.html   # single-file build (generated by scripts/build_standalone.py)
scripts/build_standalone.py   # builds standalone.html and the offline snapshot
tests/test_contracts.py       # reference-case and guardrail regression tests
tests/test_features.py        # live Stage E, routes, capabilities, artifacts, organ bundles
```

## API

Reads are synchronous. Long stages accept a POST that submits a job; poll `GET /jobs/{id}`.
Every `/stage/*` GET also accepts `engine=<JSON>` to address a parameterised result.

| Route | Purpose |
|---|---|
| `GET /organs` | organs (implemented / planned), including valid bundles |
| `GET /organs/{organ}/layers` | cell layers + atlas stats |
| `GET /organs/{organ}/layers/{layer}/states` | states with role + master TFs |
| `GET /runs?organ=&layer=&source=&target=&species=&route=` | per-stage cached / not_computed / running |
| `GET /stage/A?organ=` | evidence catalog (36 rows) + drug-engine health |
| `GET /stage/B?organ=&layer=` | atlas summary + states + source datasets |
| `GET /stage/C?organ=&layer=&route=scenicplus\|celloracle` | GRN hubs (SCENIC+ reference) or not_computed |
| `GET /stage/D?organ=&layer=&source=&target=&species=` | TF recipe + modules (reference transition) |
| `GET /stage/E?organ=&layer=&source=&target=` | compound nominations + curated cocktail + single-cell confirm |
| `GET /stage/F?organ=&layer=&source=&target=&species=` | PertFormer fate-proximity Δ per species |
| `POST /stage/{B\|C\|D\|E\|F}/run` | submit a job → `{job_id}`; invalid bodies → 400 |
| `GET /jobs/{job_id}` | status, `result_uri`, `error`, `requires` |
| `GET /compute/status[?probe=1]` | engine availability, organ-bundle validity, optional network probe |
| `GET /results` | index of durable result artifacts |
| `GET /provenance` · `GET /meta` | source sessions and artifacts · meta, organs, stages, defaults |

A non-reference or non-computed response carries `requires`: the concrete list of what
is missing (packages, weights, input files, GPU). A response served from a stored
artifact carries `served_from: "artifact"`.

## Scientific-integrity guardrails (handoff Section 8, enforced in code)

1. **Never fabricate outputs.** A stage returns real reference data, a stored artifact
   for the identical request, or `not_computed` with its requirements. Reference handlers
   decide only from the shipped reference data, so an artifact can never pull lung
   numbers onto another combination (a regression test covers this).
2. **In-silico ≠ validated.** Recipes, compounds and fate deltas carry
   `"evidence":"in_silico"`, and the UI frames them as hypotheses.
3. **Species is a real parameter.** Stage F differs by species (human Δ +0.107, mouse Δ −0.090).
4. **Modality gaps respected.** Only the lung epithelial SCENIC+ GRN was inferred. The
   CellOracle route is never served from the SCENIC+ table.
5. **Cache keys include engine parameters.** An artifact is served only for an identical
   identity: stage, organ, layer, source, target, species, route and engine parameters.

## What's real vs. what needs external compute

Every number served is extracted from the artifacts in `data/reference/` (see
`GET /provenance`). Recomputing an uncached combination needs inputs that are not in
this bundle: the integrated sub-atlases (`data/external/`), CellOracle `.links`, and the
~12.8 GB PertFormer weights on a CUDA GPU. Those requests fail with the missing items
listed. A live LINCS/Tahoe query runs when `requests`, `pandas`, `scipy` and network
access are present, and its result is stored as an artifact.

## Offline mode

`frontend/standalone.html` embeds two things. The first is the seed payload. The second
is a snapshot of the backend's own responses for every path the UI requests, which is
generated at build time. For the default transition of each layer, offline numbers match
the live backend. Other transitions fall back to the seed, which reports them as not
computed. Rebuild after changing the frontend or the backend:

```bash
python3 scripts/build_standalone.py
```

Running actions (the Request-computation button) needs the live server, so offline it is
disabled with the reason shown.
